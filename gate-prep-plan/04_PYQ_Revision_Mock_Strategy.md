# J. Topic-wise PYQ Strategy + Completion Checklist

## J.1 The per-topic protocol (why: PYQs convert theory into exam marks; they are the highest-yield activity per hour)

1. **Learn theory** (Block 1) → **same day/next day**, solve that topic's PYQs 2017→2026 in chronological order (oldest first: difficulty ramps up toward 2026, and older papers teach the basics of the pattern).
2. **Solve ALL** — for 🔴 topics that's typically 8–20 questions over 10 years; 🟠 ~5–15; 🟡 ~3–8; 🟢 read solutions only.
3. **Order of years:** chronological for learning (Phase 1–2); **reverse chronological (2026→2017)** in the Phase 3 re-pass and in mocks (recent papers define the current pattern).
4. **Repetition rule (spaced):** solve once when learning → **re-solve misses after 7 days** → **re-solve all starred questions (wrong or slow) after 30 days** (Phase 3–5 slots handle this).
5. **NAT/MSQ discipline:** GATE publishes no official per-topic marks, and non-MCQs are 35–50% of the paper — always re-solve NAT questions to the exact numeric answer, no "option recognition".
6. **Mistake notebook entry for every miss** (format in M).

Do not buy "10-year DA PYQ books" — they don't exist legitimately; anything older is made-up or recycled CSE questions (which, to be fair, are useful: **CSE PYQs in shared topics are valid DA practice** — probability, linear algebra, DS/algo, DBMS questions transfer directly).

# K. Revision System (what to revise, exactly when)

## K.1 Daily (45–60 min, non-negotiable — Blocks 4–5 of the weekday template)

- **D+1 rule:** yesterday's mistake-log questions, re-solved from scratch (not re-read).
- Formula-book current subject: read the 1–2 pages created this week.
- 10 flashcards (formulas/traps) — spaced queue.

## K.2 Weekly (weekend, 2.5 h inside the weekend template)

- Re-solve the week's **starred** PYQs (wrong or >2×-expected-time).
- One-page "week sheet" per subject: formulas + traps + 3 hardest questions (by hand, no copying).
- 30 min: older-week flashcard decks (D+7 rule).

## K.3 Monthly (last weekend of each month, 4 h)

- **Full subject sweep:** for each subject finished that month, re-derive its formula page from memory, then check.
- One sectional test on the *earliest* finished subject (so nothing goes cold).
- Mistake-log triage: mark questions that failed twice → "danger list" → these get re-solved weekly in Phase 4–5.

## K.4 Formula book rules

- One A5 page (or one note card) per **topic**, not per subject — e.g., "Cache AMAT", "Banker's", "B+ tree order", "PCA", "CLT & CI", "A* admissibility".
- Format: formula → 1-line condition of validity → 1 mini-example → classic trap.
- Written by hand during PYQ solving (never copied from a book) — this is why it sticks.
- By 10 Jan you should have ~90–100 cards; Phase 5 runs the full deck every 2 days.

## K.5 Spaced repetition schedule (for starred PYQs + formulas)

| Age | Action |
|---|---|
| D+1 | Re-solve yesterday's misses |
| D+7 | Re-solve week's starred; flashcards |
| D+30 | Monthly sweep + danger-list re-solve |
| Phase 5 | Danger list every 3 days; full formula deck every 2 days |

# L. Mock-Test Strategy

## L.1 Schedule (why: mocks before ~70% syllabus completion waste a test; after, they don't)

| When | What | Count |
|---|---|---|
| Phase 1 (W4+) | Subject mini-tests (30–45 min) every weekend | ~6 |
| Phase 2 (W7+) | Full sectional tests (90 min, 2 subjects) every weekend | ~6 |
| 3 Jan | First full CS mock (diagnostic, expect a low score — it's a baseline) | 1 |
| W13–14 | Full DA mocks (real 2024/25/26 papers, timed) + full CS mock 2 | 3–4 |
| Phase 4 | Full CS ×3, full DA ×2 (test series from any major provider; alternate papers) | 5 |
| Phase 5 (Feb) | Alternate-day mocks: CS ×3–4, DA ×3, including 2 on the exact exam-time slot (2:30–5:30 pm is common for CS/DA — set your body clock) | 6–7 |
| **Total** | | **~12 full (6 CS + 5 DA) + ~18 sectional/mini** |

## L.2 Mock protocol (3-hour test → 3-hour analysis, same weekend day)

1. Timed, exam interface, no pauses. OMR-style discipline: mark questions as Sure / Guessed / Skipped.
2. **Analysis pass 1 (60 min):** every wrong + every guessed-right question → mistake log with error code (M).
3. **Analysis pass 2 (60 min):** time-per-question audit — questions taking >2.5 min/mark get a "slow" tag even if correct.
4. **Analysis pass 3 (60 min):** strategy audit — attempt order, skip discipline, MSQ/NAT usage; write ONE concrete rule change for the next mock.
5. Next 3 days: the repair topics from pass 1 (this is the actual score gain).

## L.3 Mistake categorization (use codes in the log)

| Code | Type | Fix |
|---|---|---|
| C1 | Conceptual gap | Re-learn topic; 10 fresh questions; add to formula book |
| C2 | Calculation slip | Redo by a cleaner method; practice mental arithmetic; write intermediate steps |
| C3 | Silly (misread, wrong option transferred) | Read-question-twice rule; underline quantifiers in questions |
| C4 | Time management | Per-question time caps (1-mark: 2 min, 2-mark: 4 min first pass); skip-and-return |
| C5 | Guessing loss (MCQ) | Guess-stop rule: attempt MCQ guesses only when you can eliminate 2 options |
| C6 | "Knew it, froze" (exam pressure) | More timed mocks; simulated-slot practice |

## L.4 Score-improvement loop after each mock

- Target: **+5–8 marks per mock cycle** via: (a) C1 topics repaired, (b) C4 skip-discipline, (c) C5 guess-stop.
- Track one line per mock: `Score | Attempted | Accuracy | C1 | C2 | C3 | C4 | C5 | time-per-mark`.
- If score stalls 2 mocks: the bottleneck is C1 in Tier-1 topics → go back to PYQs, not to more mocks.

# M. Mistake-Log System

**Format (one row per mistake — spreadsheet or notebook):**

| # | Date | Source (year/mode) | Subject–Topic | Q summary | Code (C1–C6) | Root cause (1 line) | Fix (1 line) | Re-solve date | Re-solve ✅ |
|---|---|---|---|---|---|---|---|---|---|

**Rules:**

1. Every wrong or guessed-right question enters **within 24 h**.
2. Re-solve on the D+7 schedule; only mark ✅ when solved **from scratch, fast and correct**.
3. Two failures = danger list → weekly re-solve until the exam.
4. Sunday skim: read only the "root cause" column — patterns emerge (e.g., "3 of 5 errors are FD-closure arithmetic").
5. Phase 5: the danger list + starred PYQs **are** the revision.

## M.2 Classic GATE trap list (pre-seed your log with these — drawn from recurring PYQ patterns)
**CSE:** post-increment order in C expressions · `sizeof` array vs pointer · recursion depth vs stack · Master theorem conditions not met (use recursion tree) · Dijkstra with negative edges · Kruskal vs Prim on disconnected graphs · counting context switches in RR · EMAT double-counting TLB+cache miss · Banker's: safe state ≠ every sequence safe · FIFO anomaly (Belady) · FD closure arithmetic slips · BCNF decomposition that loses dependencies · conflict vs view serializability edge cases · B+ tree "order" convention (max children vs max keys) · TCP sequence numbers count SYN/FIN · CIDR host count off-by-network/broadcast · CRC: append vs divide order · LALR vs SLR conflict counting · SDT with inherited attributes on left-recursive grammar · Rice's theorem applicability conditions.
**DA:** exponential memorylessness direction · Poisson merging of independent streams · tower rule misuse · CLT applies to sums/means (not to n too small) · one-tailed vs two-tailed p-values · χ² test degrees of freedom · eigenvector scaling/sign in PCA · PCA maximizes variance, not class separation · k-means result depends on initialization · single vs complete linkage on chained clusters · ridge shrinks but doesn't zero (lasso does — lasso isn't in syllabus, ridge is) · SVM margin 2/‖w‖ · naive Bayes independence assumption vs conditional independence in Bayes nets · alpha-beta pruning value depends on move ordering · A*: admissible ⇒ optimal, consistent ⇒ no re-expansion · Python mutable default argument shared across calls · Python integer division `//` vs `/` · set/dict ordering assumptions.
